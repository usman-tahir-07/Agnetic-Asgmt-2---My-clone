# How I Study and Work

## How I learn best

I learn best from short, clear explanations that cover the important concepts first. If a topic is big, I break it into manageable sections and go through them one by one, each with an example and a few practice questions. Long walls of theory without examples don't stick in my head.

When something in an explanation or answer is unclear, I ask follow-up questions straight away instead of pretending I understood. A quick question now saves a lot of confusion later.

## Preparing for quizzes and exams

For quizzes, my routine is:

1. Revise the key points of the topic first, the stuff that is most likely to come.
2. Make or use a concise revision sheet, a short summary I can read quickly before the quiz.
3. Test myself with MCQs and practice questions to find the parts I don't actually understand yet.
4. Go back and fix those weak parts.

## My coding setup

I use my personal laptop running Windows. For database work I use Microsoft SQL Server with SQL Server Management Studio (SSMS). For assembly exercises I use the EMU8086 emulator. For web work I write HTML, CSS and JavaScript files and run a Python Flask backend.

One rule I follow: the code has to match the tool I'm actually using. EMU8086 syntax is not the same as other assemblers, and T-SQL in SQL Server has its own way of doing things, so an answer written for a different environment is useless to me even if it looks correct.

## How I use AI tools in my studies

I use ChatGPT as a study helper. Mostly I use it to:

- explain concepts in simple language,
- prepare revision material and practise quiz questions,
- write and understand SQL queries,
- troubleshoot code when I'm stuck,
- improve my project files.

I want answers that are accurate, straightforward and suitable for a university student. If an answer feels unnecessarily complicated, I ask for shorter or more natural-looking code. But I use AI to help me understand and complete work, not to skip the understanding part. I still check and understand the final result myself.

## How I approach an existing project

When I work on a project that already exists, like the CaseTrack website, I first look at the existing files and try to keep the project's structure and technologies. I don't replace everything without a good reason. Rewriting from scratch feels productive but usually creates new bugs.

## How I debug

- Read the error message properly and try to understand what caused it.
- Figure out which layer the problem is in: frontend, backend route or database query.
- Test that layer on its own (for example, run the SQL query directly in SSMS).
- Fix one thing at a time and test again.
